@@ fiat @@multi-agent coding agent

Terminal-native, provider-agnostic. A request is classified, planned, implemented, tested and reviewed by separate agents with shared runtime state. repo · read the source · orchestrator.py · pypi: fiat-pup

request→classify→planner→coder→tester→reviewer→approved↺ fail → coder
  • Classify: SIMPLE goes to one Coder with full tools; COMPLEX runs the full workflow.
  • Role permissions: Planner and Reviewer get read-only tools (read, list, glob, grep). Coder adds edit, multi-edit and run_command. Tester gets only run_command.
  • Feedback loop: a test failure or review rejection returns to the Coder with prior test results and findings, capped by FIAT_MAX_AGENT_ITERATIONS (default 3), then it stops and flags manual review.
  • Providers: modules for Anthropic, Gemini and OpenAI behind a factory; README and résumé also list OpenRouter and Groq. Slash commands include /provider, /model, /context (tokens and cost).
Limits. Pass/fail and approval are detected by searching reply text for FAIL and APPROVED, which is simple but brittle compared to structured output. Alpha-stage; not comparable to large commercial coding agents.
@@ sage @@research & presentation studio

One topic in, a cited Markdown article and a slide deck out. repo · backend · frontend · supabase · example article · live demo (per résumé)

router→research→planner⇉workers × N→reducer
  • Graph, not one prompt: backend/app/core/agent.py defines five LangGraph nodes with a conditional edge after the router, so research, planning, parallel drafting and assembly can each be bounded, retried and inspected.
  • Parallelism: sections fan out via Send; a semaphore (3 by default in code) and exponential backoff on rate limits keep providers happy.
  • Per résumé: Tavily research with dedup; nine slide layouts; Beamer PDF and editable PPTX; slide linter plus single-slide LLM repair; bring-your-own-key with Fernet-encrypted keys; Supabase auth with row-level security. crypto.py, auth.py, slides.py exist in the backend.
Deployment (Render + Vercel) is described in the README. This site cannot call the backend itself.
